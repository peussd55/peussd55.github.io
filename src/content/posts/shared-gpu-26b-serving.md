## 문제

- 쓸 수 있는 하드웨어는 96GB GPU 한 장, 그마저 다른 팀 서비스가 약 69GB를 사용 중. 실제 예산은 약 34GB
- 26B 모델의 원본 가중치는 이 예산에 들어가지 않음

## 고른 것과 버린 것

- 디스크에는 원본을 두고, 올릴 때 8비트 부동소수(FP8)로 바꾸는 방식을 선택. 양자화 방식을 바꾸거나 되돌릴 때 설정 한 줄이면 됨
- 미리 양자화해 둔 가중치를 받아 쓰는 방식은 제외 — 방식을 바꾸려면 가중치를 다시 받아야 함
- 정수 양자화 계열은 제외 — 이 GPU가 FP8을 하드웨어로 지원해 이점이 없음
- 지금 어떤 방식으로 서빙 중인지는 문서가 아니라 디스크 용량으로 확인. 50GB면 원본, 미리 양자화한 것이면 약 26GB
- 나눠 쓰는 예산은 늘리지 않음. 다른 팀 서비스의 안정이 내 측정값보다 우선

## 측정값

- 평소 예산(약 34GB): 첫 토큰까지 중앙값 0.10초 · 동시 8명까지 쾌적 · 16명부터 대기 발생
- GPU를 전부 쓸 때(측정 시간에만): "첫 토큰 95%가 1초 안 + 요청의 95%가 초당 20토큰 이상"을 동시에 만족하는 최대 동시 접속 = 128
- 동시 128 유지에서 첫 토큰 95% 0.386초 · 초당 3,537토큰 · 오류 0
- 28회 측정 · 약 1만 8천 요청 · 재현 8회 · 내가 센 값과 서버 계측값의 차이 0.2% 이내
- 동시 접속 자리를 두 배(256)로 늘려도 처리량은 11%만 증가. 병목은 메모리가 아니라 생성 연산

## 한계와 다음

- 128은 모델 서버에 직접 붙여 측정한 값. 음성인식과 음성 합성까지 포함한 전체 통화의 한계는 아님
